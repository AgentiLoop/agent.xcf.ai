## 「ゴールを与えると、そのゴールに到達するまで止まりません」

Auto-Pilot は Mac 版 Agent! の `/auto` コマンドです。README の Auto-pilot セクションによると: メインタブまたは任意の LLM タブ上で、タスクループを無人のサイクルとして、ゴールに到達するか、時間予算を使い切るか、Stop を押すまで実行します。サイクル数の上限も、サイクルごとのイテレーション上限もありません。サイクルのタスクが終了してもゴールに到達していなければ、次のサイクルが自動的に始まります。

| コマンド | 動作 |
|---|---|
| `/auto <goal>` | LLM が到達したと報告するまでゴールに向かって作業する |
| `/auto 4h <goal>` | 同じだが、4時間後に停止する（`30m`、`1.5h` も使える） |
| `/auto` | まずプロジェクトをレビューし、それからゴールを尋ねる |
| `/auto history`, `/auto last`, `/auto #N` | 過去のゴールを一覧表示し、最新または N 番目を再開する |
| `/auto status` / `/auto stop` | セッションを表示する、または現在のサイクルの後に終了する |

「タスクの強化版だと考えてください」は正しいメンタルモデルです。各サイクルは、同じツール、同じガードレール（read-before-edit、goal_state の証拠、シェルのブロックリスト）、同じ `done()` の契約を持つ、*まさに*通常の Agent! タスクです。Auto-Pilot が加えるのは、その周りを囲むループです。サイクルの要約はプロジェクト内の `.agent/autopilot/progress.md` に追記され、次のサイクルのプロンプトに渡されるので、各サイクルは前のサイクルが何をし、何を仮定し、何をやり残したかを読むことから始まります。セッションが終わるのは、LLM が最終要約を `AUTOPILOT: GOAL REACHED` で始めたときだけです。エラーやキャンセルで要約がまったくないまま終わったサイクルがセッションを終わらせることはありません。次のサイクルが待つ時間が長くなるだけで、15秒、次に30秒、次に60秒、最大5分までです。

「デフォルトでは … 時間枠はありません」は文字どおりです。期間を指定せずに `/auto <goal>` を実行すると、ゴールに到達するか、あなたが止めるまで走り続けます。上限が欲しければ、`/auto 4h <goal>` で設定できます。アクティブなセッションはアプリの再起動後も残ります。終了やクラッシュで一時停止し、次回起動時にそれぞれのタブで次のサイクルから再開します。

## 「Auto-Pilot にはキルスイッチがあります」

止める方法は3つあり、それぞれ動作が異なります:

- **Stop All**（すべて停止、ボタン）は、すべてのタブのすべての Auto-Pilot セッションを終了し、実行中のタスクをすべて停止します。`RunStop.swift` のコメントに明記されています。単一タスクの停止、つまり Esc や停止ボタンでは Auto-Pilot は走り続け、Stop All がそれを終了させます。
- **`/auto stop`** は現在のサイクルが終わった後にセッションを終了し、サイクルの合間であれば即座に終了します。現在のサイクルは最後まで走ることが許されます。
- **`/auto stop all`**（`stopall` や `stop-all` も可）は、Stop All を押すのと同じで、マウスに手を伸ばしたくない人向けです。`AutoPilot.swift` の中で `/auto stop` の直前に処理されます。

投稿文では `auto stop` を「現在の Cycle だけ」を終了すると説明しています。より正確に言えば、現在のサイクルの後に*セッション*を終了するもので、サイクル自体は自然な終わりまで走ります。これが進捗ログと git の履歴をきれいに保っている理由です。

## 「11月には … 同じプロジェクト上で複数の Auto-Pilot を実行」

ここは投稿文の中で、出荷済みの機能ではなくロードマップ項目にあたる部分で、どちらがどちらかをはっきりさせておく価値があります。今日の時点で、Agent リポジトリの main ブランチには *Auto-Pilot: multiple tabs per project — per-tab progress, shared registry, auto/forced git worktree isolation, shared memory from worktrees* というタイトルのコミットがあります。それが土台です。各タブは自分の進捗ログを持ち、タブ同士が互いに登録し合い、2つの Auto-Pilot が同じファイルを編集しそうになると、それぞれ別の git worktree が与えられます。まだリリースには含まれておらず、1.1.87 タグの後に入りました。リリースは毎月1日に出るので、11月1日のリリースが皆さんの手元に届く最も早いタイミングで、「他のタブを生成するタブ」の部分は、投稿文によれば同じ時期に予定されています。

## 「マリオカート風クローン GoKart」

GoKart は Auto-Pilot がその寿命の大半を費やしてきたプロジェクトです。[以前の記事](/blog/gokart-built-on-auto-pilot/)では、最初の午後を進捗ログそのままに詳しく扱っています。サイクル1で Godot 4 をインストール、ハンドリングをユニットテストできるように `VehicleBody3D` ではなくカスタムのアーケード物理を選択、サイクル2でドリフトスパークとブーストブラー、サイクル3でトラック、サイクル4でアイテム、迷い込んだタブ文字での停滞、Stop All、そしてすべてのシェル実行に `perl -e 'alarm'` の時間制限をかけてから15個の機能を立て続けに出荷した2回目のセッション。

それは止まっていません。[GoKart リポジトリ](https://github.com/AgentiLoop/GoKart)は、10月1日 12:39 の最初のコミットから、10月3日の夕方までに71コミットに達しました。最近のコミットはマリオカート64のチェックリストのように読めます。Sunset Speedway の Toad's Turnpike 風の交通、Green Hills の Moo Moo Farm 風の Monty Mole、ライブのアトラクトデモ付きタイトル画面、リザルトボード、HUD に描かれたアイテムウィンドウ。それぞれが独自のテストファイルと `tools/*_check.gd` スクリプトとともに入っています。モデルは依然として画面を見ることができず、機能が存在することを別の方法で証明しなければならないからです。投稿文の「20時間以上」は、それらのセッションの実時間の合計です。読むより遊びたいなら、[GoKart 0.0.1](https://github.com/AgentiLoop/GoKart/releases/tag/v0.0.1) を macOS、Windows、Linux 向けにダウンロードできます。
